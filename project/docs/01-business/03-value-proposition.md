# Propuesta de valor

**Estado recomendado:** `READY_FOR_IMPLEMENTATION`
**Gate operativo aplicable:** `READY_FOR_IMPLEMENTATION` indica madurez documental, no permiso operativo por sí solo. Prevalecen `CURRENT_STATUS.md` y `machine/roadmap_gates.json`. Con el estado global actual `READY_FOR_SPRINT_0`, este documento solo puede guiar tareas permitidas por Sprint 0. No autoriza UI visible, Dashboard, Onboarding ni módulos funcionales hasta alcanzar `READY_FOR_VISIBLE_FEATURE_DEVELOPMENT`.


## Propuesta central

VipWeb ofrece un ecosistema modular que permite al usuario entrar por un punto común, entender su estado, continuar donde lo dejó, activar módulos y recibir acompañamiento operativo sin depender de una web monolítica ni de integraciones rígidas.

## Diferenciales

| Diferencial | Valor |
|---|---|
| Core mínimo | Evita monolito y permite crecer por módulos. |
| Contratos de módulo | Añadir servicios o webs sin rediseñar el sistema completo. |
| Dashboard como centro | Reduce pérdida de contexto y mejora continuidad. |
| Onboarding progresivo | Activa sin sobrecargar. |
| Gamificación sobria | Refuerza progreso real, no decoración. |
| IA operativa controlada | Ayuda a mantener, auditar y ampliar sin autonomía peligrosa. |
| Doctor + evidencias | Convierte calidad documental y técnica en gate verificable. |

## Promesa MVP

En MVP, el usuario debe saber: qué puede hacer, qué módulos existen, cuál es su siguiente paso, qué progreso ha realizado y qué partes del sistema están sanas o requieren atención.
