# 01 Experience Personality

**Estado recomendado:** `READY_FOR_IMPLEMENTATION`
**Gate operativo aplicable:** `READY_FOR_IMPLEMENTATION` indica madurez documental, no permiso operativo por sí solo. Prevalecen `CURRENT_STATUS.md` y `machine/roadmap_gates.json`. Con el estado global actual `READY_FOR_SPRINT_0`, este documento solo puede guiar tareas permitidas por Sprint 0. No autoriza UI visible, Dashboard, Onboarding ni módulos funcionales hasta alcanzar `READY_FOR_VISIBLE_FEATURE_DEVELOPMENT`.


## Propósito
Definir la personalidad de experiencia sin convertirla en estilo decorativo.

## Personalidad UX
VipWeb debe sentirse como un ecosistema que acompaña: claro, continuo, modular, tranquilo y útil. La interfaz debe explicar el siguiente paso, conservar contexto y evitar sobrecarga.

## Reglas
- El usuario siempre debe saber dónde está, qué puede hacer y qué viene después.
- Los módulos deben sentirse conectados por AppShell, no como páginas aisladas.
- La gamificación debe reforzar progreso real, no presión.
- Los mensajes de error deben ser accionables.
- La IA debe presentarse como ayuda asistida, no como autoridad autónoma.

## Criterios de validación
Cada pantalla MVP debe tener estado vacío, bloqueado, error y éxito con copy específico.
